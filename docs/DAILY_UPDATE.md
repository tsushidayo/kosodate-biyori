# こそだて日和の毎日の更新

毎朝7時、日本時間の既存タスク「こそだて日和を更新」で調査と反映を行う。本人だけが見られるSitesの公開範囲を保ち、GitHub `tsushidayo/kosodate-biyori` と共有情報を同期する。依頼済みのタスクを重ねて新設しない。

## 掲載する内容

- 出産準備、毎日のお世話、食事、子どもの教育・遊び、育児グッズ、支援制度、子連れのおでかけを中心にする。「子ども」の語があるだけの研究発表・会議・活動報告・個人の日記・販促だけの記事は追加しない。
- 「誰が、何を準備・確認・利用できるか」を短い独自要約と具体的なポイント2〜3個で記録。ニュースは家族が使える変更・申請・募集・提供開始などを優先する。原公開日、元ページの更新日、確認日を区別する。不明な公開日を今日の日付で埋めない。
- おでかけは施設の公式案内を確認。都道府県・市区町村、屋内/屋外、予約、授乳室等の確認できた項目、休館・休止を保存する。全国の施設を順番に調べ、一部地域ばかりを増やさない。
- 年齢を原典で確認できない場合は推測しない。制度は金額・期限・所得等の条件も確認する。全国1,741自治体の索引と、個別制度を確認した件数を混同しない。

## SNS・動画

- Instagramの動画とYouTube等のショート動画は同じ動画一覧へ。Instagram欄には形式を確認した画像・カルーセルだけを載せる。`/p/`というURLだけで画像とは判断しない。動画を含む混合カルーセルは動画側へ。180秒を超えると分かっている動画はショート動画に入れない。長さ不明は未確認と表示する。
- 使い方、レシピ、出産準備、教育、グッズ、子連れのおでかけを優先し、あるあるばかりを増やさない。元の投稿日・実在する個別URL・複数ラベルを保持する。`data/social-curation.json` の `instagramPosts` と `shorts` を更新する。
- 地震・防災・災害・備蓄・避難・事故・感電・やけど・誤嚥・窒息等の動画は、子どもが登場しても除外。実際のタイトル・説明・本文に育児関連語がある動画だけ。一般動画に後付けのラベルで育児語を補わない。
- 内容未確認のSNS投稿はその状態を明示。医療や制度の根拠には使わない。Xは原文を公式埋め込みで表示。投稿全文を独自に転載しない。各SNS1,000件以上は目標であり、架空の件数・日付・投稿を作らない。取得枠がないサービスへ勝手に課金しない。

## 通販・フリマ

- 全商品で同じ18通販を比較。Amazon、楽天市場、Yahoo!、ヨドバシ、西松屋オンライン、アカチャンホンポ、トイザらス・ベビーザらス、ビックカメラ、LOHACO、サンドラッグ、マツキヨ、ウエルシア、イオン、クリエイト、セイムス、ツルハ、ミスターマックス、au PAYを固定対象とする。
- `node scripts/retailer-coverage.mjs data/shop.json /tmp/retailer-queue.json`で未確認の組合せを洗い出し、価格の確認先が少ない商品から調査する。同じ商品に偏らず、前回の未確認先から順番に進める。個別ページでJAN・型番・色・容量を照合し、価格・送料・個数・在庫・確認日時を保存。取得できない時は`retailerResearch`に状態と確認日を残し、取扱なしと取得不可を区別する。検索結果の金額、メーカー希望価格、推測額では埋めない。
- 18通販すべての価格が確認済みとは扱わない。送料不明の実商品価格は表へ掲載できるが、送料込み順位へ入れない。

- 表示する買い方はネット通販とフリマ。現時点で十分な店頭価格がないため、店頭購入・店舗受取を選択肢に出さない。データ上の過去の購入方法は削除せず、通販の順位へ混ぜない。
- 同じ商品で比較先を増やす。JAN・型番・色・サイズ・容量・入数・新品/中古を照合し、Amazon、楽天市場、Yahoo!ショッピング、ヨドバシ、アカチャンホンポ、西松屋等を共通の調査先にする。1メーカーの部品ばかりを増やさず、食事・衛生・おむつ・おもちゃ・学用品等を分散する。
- 商品別の検索リンクは見つけるための入口であり、確認済みの価格として数えない。確認できない送料はnull。売り切れ、数量違い、送料不明、48時間より前の価格は現在の安い順から外す。ポイントを現金価格から差し引かない。
- フリマは毎回、登録済みの個別出品を再確認し、新しい出品もウェブ検索で探す。メルカリ・ラクマ・Yahoo!フリマ等で、個別URLとモデル・色・状態・付属品・税込価格・送料・販売中を確認する。別モデルや欠品を同一条件の新品と混ぜない。
- `node scripts/marketplace-refresh.mjs input.json output.json --max=60` で登録済み出品を再確認する。robotsの禁止や403等を回避しない。取得失敗時は過去の価格と確認日を残して順位から外し、失敗を記録する。売却済み・出品終了は表示を更新する。

## 実行と保存

1. Sites `get_site`、GitHubの最新mainと収集ファイルを読む。コードを変える場合はSitesのソースヘルパーで最新状態を開く。トークンはメモリーから標準入力で使い、引数・ファイル・ログへ書かない。
2. `/api/content` を読み、今回の調査分を最新の共有情報へ統合する。既存の `collections`、別の更新、利用者の私的な設定を上書きしない。
3. ニュース・コラム・SNSの編集データをGitHubへ同期してからフィード更新を行う。本文やUIを変えた場合は型チェック・関連テスト・ビルドを通してSitesへ保存・公開する。
4. `node scripts/daily-refresh.mjs` を実行。標準入力に小さなJSONを1行で渡す：`{"url":"<Sitesの公開URL>","token":"<セッション内の値>","priceLimit":20,"marketplaceLimit":60,"outputDirectory":"<公開データだけの作業先>"}`。登録通販価格の巡回確認、登録フリマの再確認、shopのrevision付き保存、RSS・GitHub・SNSの再読込、読み戻しを行う。
5. 出力された共有care/shop/editorial/feedsをGitHubにも反映する。競合したら最新を読んで統合し直す。単に成功したと報告せず、保存先の状態・実件数・配信元ごとの成否を確認する。未取得情報を最新と表記しない。

誕生日、出産予定日、住まい、性別、保存記事、チェックリスト、通知条件、トークンは利用者ごとの情報。共有JSON・公開GitHub・ログ・タスク本文へ保存しない。

API: GET `/api/content`、POST `/api/update`、POST `/api/refresh`、GET `/api/status`。利用者の私的設定はGET/PUT `/api/profile`。共有care/shop/editorialは各8MBまで、各1.2MB超はD1内で分割保存。各SNSは最大3,000件、ニュース・コラムは各500件まで。画面の文章と見た目は `DESIGN_GUIDE.md` に従う。


## 商品・自治体の不足を見つける

- `node scripts/research-coverage.mjs data /tmp/kosodate-coverage.json`でブランド・カテゴリの偏り、個別制度が未掲載の自治体、未確認の通販を確認する。索引を詳細制度の確認済み件数に数えない。
- 商品には短い独自要約、特徴、JAN/型番、容量・サイズ・素材・適応体重、原典のある対象年齢を保存。年齢不明をallAgesとして扱わない。配送用の重量を正味容量へ流用しない。
- 個別商品の有効な購入欄や公開在庫で注文受付を確認できればavailable:trueとし、現物在庫数・決済・出荷保証とは分ける。不明はnull、売り切れ・予約は通常の順位に入れない。
- 明示的な画像リンク禁止は守る。利用制限を表示側で扱えない商品は、扱えるまで保留する。
- 18歳年度末の条件はschoolYearEndAge等で扱う。登録した生年月日なら年度境界を確認できるが、手動の年齢だけで確定できない場合は未確定として扱う。
- 大きいcare/shopも分割保存に対応。revision付き更新は1セクションずつ送り、409なら最新を再読込して統合し直す。

## 商品別の検索リンク

主要18通販の検索経路は2026年10月25日に公式のフォーム・案内・検索画面で確認。JANを優先する。クリエイトSDは日本語の検索URLが文字化けするため、JAN不明の商品では公式トップを案内する。検索結果URLは商品価格として登録しない。ツルハの数値.htmlは個別商品として扱う。送料や在庫が不明でも確認できた商品代は一覧へ表示し、送料込みの順位には含めない。

## 価格は同じ購入量で比べる

- 通常購入とまとめ買いを分ける。1袋・2袋・ケースなどを同じ順位に混ぜず、容量・枚数・セット数と商品の仕様をそろえる。おまけの容量が違うものも別の候補にする。
- 同じ通販に複数の販売店・買い方があれば、選んだ量の送料込みの総額が最も安い掲載を採用。単品を2点買う方が安い場合も、2点買えることと送料を確認できたものを比較候補に加える。単品の価格×点数は計算根拠を残し、単品の巡回処理でまとめ価格を上書きしない。
- Yahoo!ショッピング経由とサンドラッグ公式通販など、別の購入先は同額でも別カード。選んだ1件の購入URLをそのまま使い、複数の通販名やURLを結合しない。通販名と出店している販売店名は別の項目にする。
- Amazonは同じASIN・容量・セット数のプライム対象を優先して調査する。個別商品で対象を確認できたときだけ記録。ページ共通のPrimeロゴでは判定しない。会員だけの価格・送料は条件を明記する。
- 送料や在庫が確認できない場合は商品代の参考欄へ。検索結果の最安表示を、その通販全体の確定した最安額と扱わない。

## スギ薬局の店頭と仮の試算

- Sugiの比較先は公式店舗案内 https://www.sugi-net.jp/stores 。18通販と店頭1チェーンを分けて数える。全店共通の店頭価格や商品の取扱を推測しない。
- クーポンは公式FAQと券面を優先。食品（菓子類を除く）とベビーミルクは2026年8月31日更新の除外リストで確認済み。割引の仮額は実売の順位へ入れない。
- 通常単品を複数購入する場合、1品割引は1点分だけ。元からケース1包装で売っている場合と混同しない。紙とアプリを同じ1品に二重適用しない。ポイントは現金の値引きと分ける。
- 年齢・入手・期限・最低額などの利用条件を自動的に満たした扱いにしない。店頭価格と確認チェックは端末内の一時入力で、shared APIや公開データへ保存しない。

- `manualRefreshRequired:true` の通販掲載は、公式本文を再確認する。機械の価格抽出に未対応の掲載へ `refreshEligible:true` を付け直さず、未確認の日時を更新しない。手動確認の価格も48時間で現在の順位から除外する。
- `uncertainAgeRanges` は公式文で誕生日当日などの扱いを確定できない境界だけに付け、確認済みの月齢範囲とは分ける。該当する月齢では年齢条件を未確定として表示し、利用可否を断言しない。
