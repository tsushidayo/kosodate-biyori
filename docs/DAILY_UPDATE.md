# こそだて日和の毎日の更新

本人だけが閲覧できるSitesとして運用する。公開範囲を維持し、共有情報と個人の設定を分ける。日々の内容更新はD1へ保存し、画面・処理・同梱データを変更した場合はSitesの保存・公開手順も実施する。

## 更新する順序

1. Sitesの `get_site` でサイトID、公開URL、本人限定の公開範囲を確認する。返された `siwc_bypass_bearer_token` はセッション内だけで保持する。ソースを触る場合は `create_source_repository_write_credential` とSitesのソースヘルパーで最新状態を開く。
2. `/api/content` の最新内容とセクションごとのrevisionを読む。GitHub `tsushidayo/kosodate-biyori` の `collections/index.json`、新しい日付の収集ファイル、`data/*.json`、コードの更新も確認する。既存の収集ファイルを削除しない。`collections/index.json` の `files` は文字列の相対パスを新しい順に最大20件保つ。
3. 全国・都道府県・市区町村の公式案内を確認し、給付、医療費、保育、産後ケア、就学などを追加・修正する。自治体、対象年齢、所得等の条件、金額、期限、申請先、出典を記録する。1,741自治体の索引と、制度の本文を確認できた自治体数を区別する。
4. 食事・健康・安全・制度は公的な一次資料を確認する。ニュースと定番コラムを分け、公開日・更新日・確認日を混同しない。記事本文を転載せず、役立つ点を独自の短い要約にする。年齢を本文や出典で確認できない場合は未確認のままにし、見出しだけで決めない。
5. ニュースとコラムには内容に応じた複数ラベルを付ける。食事・栄養、健康・安全、園・学校、仕事・制度、家族・心などを重複して使い、既存の具体的なラベルも保つ。無関係な芸能・政局・統計だけの記事や広告だけの内容は増やさない。
6. X・Instagram・ショート動画を別々に調べ、下記の採否基準で `data/social-curation.json` を更新する。登録した配信元も確認し、確認済みの個別動画を追加する。毎日調査しても有用な新着がなければ無理に件数を増やさず、古い動画の日付も変更しない。
7. 価格は同じ型番・容量・個数を区別し、税込価格、送料、最低注文額、クーポン条件、在庫、確認時刻を記録する。JAN・サイズ・現行品かどうかも確認する。通販・店舗受取・店頭価格を区別し、販売先の数を水増ししない。確認できる範囲で上位10店を比べ、架空の価格や空の順位は追加しない。未確認の価格は確認日を新しくせず、48時間を超えた価格を最安候補から外す。
8. 変更前に最新revisionを再読し、他の更新を保って統合する。`POST /api/update` へセクション全体と `expectedRevision` を送る。同時更新で409になったら読み直して統合する。`POST /api/refresh` でRSS・GitHub収集・SNS承認結果を反映する。
9. `/api/content` と `/api/status` を読み戻し、`storageAvailable: true`、revision、件数、RSS/GitHub/承認データの結果を確認する。失敗した出典や未確認のページを結果に含める。更新後の共有care/shop/editorial/feedsをGitHubの `data/*.json` にも保存し、同時更新を上書きしない。
10. GitHubのコード変更は内容を確認し、必要な変更をSites側へ反映する。型チェック・関連テスト・ビルドを通して、同じソースを保存・公開する。公開範囲を維持し、完了後のSite URLとGitHubのcommitを確認する。

誕生日、出産予定日、住まい、性別、保存記事、チェックリスト、個人の通知条件、トークンを公開GitHub・共有JSON・ログ・タスク本文へ保存しない。年齢による表示はブラウザーと利用者別プロフィールで行い、動画やXへのURLに誕生日を付けない。既存の別用途のXリポジトリには書き込まない。

## SNSとショート動画の掲載条件

- XとInstagramはそれぞれ1,000件以上を目標に、妊娠・出産・育児・子育て・子どもの教育・親子のおでかけ・支援制度に関連する実在の投稿を追加する。体験談や意見・議論、正確さが未確認の内容も対象。関連性の確認を事実確認と混同せず、「内容未確認」「体験談」などを表示する。架空の投稿・日付・反応数で件数を埋めない。
- Xは実在する個別URL・投稿IDを確認し、reviewsへ関連性の採否と複数ラベルを記録する。InstagramはinstagramPostsへ記録。投稿全文を独自にコピーせず、公式埋め込みと元リンクで読む。個人の見解を医療・制度ガイドの根拠には使わない。
- 動画の表示名は「ショート動画」。地震、防災、災害、備蓄、避難、事故、感電、やけど、誤嚥、窒息などの対策を扱う動画はすべて除く。子ども向けの事故動画も例外にしない。既存の不適合動画も除去する。
- 動画は実際のタイトル・説明・短いキャプションに、妊娠・出産・育児・子育て・赤ちゃん・親子・離乳食・保育・学校・教育などの関連語があるものだけを登録する。一般動画にラベルや定型的な「子育て」の説明を付けて条件を満たしたことにしない。
- 個別動画の公開状態・長さ・埋め込み可否を確認し、不明な項目は未確認とする。YouTube ShortsはvideoFormat:shorts、通常の短編はshort-video、Instagram動画はinstagram-video。公開日を確認日で上書きしない。自動再生せず、読み込めないときの元リンクを残す。
- 共有されたshare.googleは検索への入口を含む。検索結果ページを個別動画として埋め込まない。取得できなかった投稿を確認済み・視聴済みと扱わない。取得サービスの利用枠がない場合は勝手に課金しない。
- 元のcollectionsはサイト掲載の採否にかかわらず残す。新しい収集ファイルもmanifestに追記し、既存のレビュー・ラベル・年齢情報を保持する。

## 取り込み処理

`POST /api/refresh` は登録済みRSS最大24件、収集一覧とファイル最大20件、固定の `data/social-curation.json` を取得する。ニュースとコラムは各500件まで。RSS配信元による転載条件を確認し、有効なXMLを取得できたURLだけを登録する。

GitHubの収集対象は `schemaVersion: 1`、`updatedAt`、`files` を持つ `collections/index.json`。`files` の `collections/YYYY-MM-DD/ファイル名.json` だけを取得する。投稿ID・URL・投稿者・日付・数値を検証し、同一投稿は新しい収集日時を優先する。ファイルは各600KB・合計8MB、取得は各7秒まで。SNS編集データは5MBまで。外部URLや親ディレクトリへは移動しない。最大46件の外部リクエストになる。

取得した投稿は承認レビューを照合し、承認済みだけをX欄へ反映する。明示された不採用を優先し、反応数の再取得で承認・ラベル・年齢情報を失わないようにする。Instagramはinstagram配列、動画はshorts配列へ保存する。各プラットフォームは最大3,000件。取得失敗時は既存の確認済み内容を維持し、結果の `github` / `curation` / RSSごとの成否を確認する。

共有editorialは最大8MB。保存内容が1.2MBを超える場合は、D1の行サイズ上限を超えないよう内部で分割する。通常のAPIでは分割前と同じ内容を読み書きできる。内部の分割ポインターを更新データとして送らない。

## APIと補助スクリプト

- GET `/api/content`: 共有care / shop / editorial / feeds、セクションごとの更新日・revision、保存先の状態。
- POST `/api/update`: `{section,payload,expectedRevision?}` または `{updates:[...]}`。競合を確認する更新は一度に1セクションを送る。
- POST `/api/refresh`: 登録RSS、GitHub収集、SNS承認データを取得する。
- GET `/api/status`: 保存先・更新日・revision・件数。
- GET `/api/municipalities`: 全国の自治体索引。各制度の確認済み件数とは別。
- GET / PUT `/api/profile`: ログイン中の利用者ごとの設定。PUTは `{profile,expectedRevision?}`。GETのrevisionを渡し、別の端末の変更を上書きしない。

`scripts/update-site.mjs` はJSONを標準入力で受け取る。形式は `{ "url": "<公開URL>", "token": "<セッション内の値>", "updates": [{"section":"shop","path":"<共有JSONの絶対パス>"}], "refreshFeeds": true }`。秘密を引数やファイルへ保存しない。価格取得の補助は `scripts/price-refresh.mjs` を使い、同一商品・個数・送料・税込表示・在庫を再確認する。

ブラウザー通知は、次にサイトを開いたときの掲載価格の比較に対応する。閉じている間の配信・メール送信は未接続。画面・文章の変更は [DESIGN_GUIDE.md](DESIGN_GUIDE.md) に従う。

## 購入方法とフリマ

- 「店舗で買う」は確認できた店頭価格だけ。ネット通販やネット注文後の店舗受取を混ぜない。店舗受取は別のタブへ表示する。店頭価格を取得できない商品に通販価格を代用しない。
- メルカリなどは実在する個別出品を確認し、型番・色・状態・新品/中古・数量・付属品・送料・販売中/売り切れを記録する。売り切れや送料不明の出品は安い順の比較から外す。中古は明示し、通常の比較では利用者が中古を含めるか選べるようにする。
- 商品の公式データはscripts/import-pigeon-catalog.mjsなどで再取得し、現在の共有データを保って追記・更新する。一般の送料条件だけから個別注文の送料を作らず、未確認はnullとする。
